# 一键通话（WxAutoVideoCall）

给不太会用智能手机的老人用的安卓应用：**点一下桌面图标，就能给指定的家人打微信视频通话。**

起因：我奶奶不会主动打视频给我。她会接，但不会拨。同时她平时会用微信「视频号」看视频，
说明微信她自己是用得起来的，只是「找到我 → 点开聊天 → 点 + → 点视频通话 → 再点视频通话」
这条链路对她来说太长了。

这个应用把那五步变成一步。

---

## 它是怎么工作的

微信**没有**任何公开接口可以拨出通话，也不能用深链直接发起视频。
所以这个应用走的是 Android 的**无障碍服务（AccessibilityService）**：它替你点微信里的按钮。

点一下图标之后，应用会自动做这些事：

```
打开微信 → 点首页搜索框 → 输入联系人名字 → 点搜索结果进聊天页
        → 点输入栏「+」 → 点面板里的「视频通话」 → 点二选一面板里的「视频通话」
        → 确认通话已拨出
```

整个过程大约几秒，中途你什么都不用做。

### 一个必须说清楚的限制

**「给谁打」这一步在技术上省不掉。** 微信的「视频通话」按钮藏在一个具体联系人的聊天页里，
不进入聊天页就不可能定位到它。所以界面上至少要有一次「选择联系人」的交互。

这不是偷懒，是为了**不拨错人**。给一个不会用手机的老人做出「有时打给你、有时打给别人」
的按钮，比多一次点击糟糕得多。

---

## 使用方式

**配置**（由懂技术的人做一次）：

1. 打开应用 → 设置 → 添加联系人，填**微信里显示的名字**
   （包括你给奶奶设的备注名，要和微信里一模一样，否则搜不到）。
2. 在这一行点 **「放到桌面」**，在系统弹框上点「添加」。
   桌面上就会出现一个以这个人名字命名的图标。
3. 进「运行环境自检」页，按提示开启无障碍服务，并按手机品牌放行后台运行。

**给奶奶用**：点桌面上那个人名的图标 → 卡片上出现两个大按钮 → 点「视频通话」。
点卡片外面任意位置就会关掉，不用找「取消」按钮。

每个家人都做一遍第 1、2 步，奶奶的桌面上就会有「给儿子」「给孙女」这样一排图标。

> 从**应用图标**（不是快捷方式）进去时，会列出所有联系人。
> 这条路径是给配置者用的，不是给奶奶用的。

---

## 为什么快捷方式这么设计

微信没有拨出通话的接口，必须靠无障碍服务替她去点微信里的按钮。
而要定位到「视频通话」这个按钮，就得先进入**某个具体联系人**的聊天页。

所以：**「打给谁」由桌面快捷方式确定，「打视频还是语音」由她点一次。**
这样她不需要在亲戚列表里找人，也不会拨错人。

## 构建

需要 JDK 17+ 和 Android SDK（platform 36、build-tools）。

```powershell
$env:JAVA_HOME = "D:\java"      # 换成你的 JDK 路径
.\gradlew.bat assembleDebug
# 产物：app\build\outputs\apk\debug\app-debug.apk
```

Android SDK 路径写在 `local.properties`（该文件不入库）：

```properties
sdk.dir=E\:\\Android\\Sdk
```

也可以直接用 Android Studio 打开本工程。

安装到手机：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

如果要做真机调试，用仓库里的脚本更省事 —— 它会编译、覆盖安装，
然后只抓本应用相关的日志（需要手机已开 USB 调试并授权）：

```powershell
.\debug-install.ps1
```

调试包带 `.debug` 后缀，不会覆盖正式包，所以正式版可以一直留在手机上。

## 出问题了怎么排查

微信改版后这个应用可能会失效。应用内置了排查手段：

1. 设置里打开「记录调试日志」；
2. 点一次拨号，让它走到失败；
3. 进「日志」页，点「复制全部」。

日志里会写清卡在哪一步、当时微信界面上有哪些控件。
**「抓当前界面」**按钮会把微信此刻的控件清单追加进日志，用来核对微信版本变化后按钮去哪了。

开发者需要的信息集中在这两个文件里（改微信适配只改这里）：

- [`WeChatSelectors.java`](app/src/main/java/com/elomary/wxautovideocall/automation/WeChatSelectors.java)
  —— 控件文案与 resource-id 候选
- [`WeChatFinders.java`](app/src/main/java/com/elomary/wxautovideocall/automation/WeChatFinders.java)
  —— 多候选降级的查找逻辑

## 已知限制

- **依赖无障碍服务**：必须在系统设置里手动开启，应用无法自己开。
- **微信改版可能失效**：所有靠界面文本定位的方案都有这个问题，
  所以定位规则被集中在一处，方便跟着微信更新。
- **锁屏状态下无法点击**：安卓的限制。应用检测到锁屏时会提示先解锁。
- **Android 10+ 的后台启动限制**：部分国产系统（ColorOS / OriginOS / MIUI 等）
  会拦截「应用去启动微信」，需要手动放行后台运行。应用的「运行环境自检」页里有针对性指引。
- **仅在中文版微信（Weixin）上验证**，国际版 WeChat 未适配。

## 隐私

应用**不联网上传任何数据**。日志只存在手机本地，靠手动复制发出来。
无障碍服务只读取微信的界面内容用于点击，不做其他用途。

## 开发约定

改代码前请先看下面这几条。它们都是**架构上的硬约束**，不是风格偏好。

### 微信控件定位必须集中管理

微信的 `resource-id` 是混淆过的，不同版本还不一样。因此本项目采取
**多套候选 + 文案兜底**的定位策略，并且把所有「怎么找到这个按钮」的知识
集中在这两个文件里：

- [`WeChatSelectors.java`](app/src/main/java/com/elomary/wxautovideocall/automation/WeChatSelectors.java)
  —— 控件文案与 resource-id 的候选值
- [`WeChatFinders.java`](app/src/main/java/com/elomary/wxautovideocall/automation/WeChatFinders.java)
  —— 多候选依次降级的查找逻辑

**不要把控件文案或 resource-id 写进流程代码。** 适配新版本微信时只应改动
`WeChatSelectors`。另外，`WeChatSelectors` 里标有 `TODO(真机)` 的 id 均未经
真机验证，在拿到真机证据之前不要把它们当成确定值，也不要删掉文案兜底路径。

### 拨号流程不能阻塞主线程

无障碍服务的回调跑在主线程，任何 `sleep` 或阻塞等待都会直接导致 ANR，
而且阻塞期间微信的节点树根本不会更新，等待是无效的。

所以流程是**「声明达成条件 + 事件驱动重试 + 每步超时」的状态机**
（见 [`CallFlowController`](app/src/main/java/com/elomary/wxautovideocall/automation/CallFlowController.java)）：
每一步声明自己的目标，控制器反复检查条件是否达成，没达成就在该步的预算内重试动作，
达成后才进入下一步。新增步骤请沿用这个模型，不要引入轮询式的 sleep。

### 失败必须可解释

出问题的现场在老人的手机上，开发者往往拿不到那台设备。任何失败路径都要往
[`DebugLog`](app/src/main/java/com/elomary/wxautovideocall/data/DebugLog.java)
里写清**卡在哪一步**以及**当时的界面长什么样**。这是排障的唯一依据。

### 提交前必须能编译

无障碍相关的代码很容易在编译期出错（猜错 API 级别、误用隐藏 API 等）。
改完请至少跑一次：

```powershell
.\gradlew.bat assembleDebug
```

一个已经踩过的坑：**不要用 `android.util.Log.format()`**，它是隐藏 API，
编译期会报「找不到符号」。改用 `String.format(Locale.US, ...)`。

### 刻意不做的事

以下几条是明确的设计边界，不是「暂时没做」，请不要顺手加上：

- **需要 root 的方案。** 目标设备是老人的手机，不会 root。
- **常驻悬浮球。** 怕误触。
- **申请「使用情况访问」（`PACKAGE_USAGE_STATS`）这类重权限。**
  判断前台应用用无障碍服务自己的窗口列表就够了，不必为此让使用者多开一个权限。
- **在拨号卡片上增加按钮。** 面向老人的界面只放「打给谁」和「视频还是语音」，
  新功能一律进设置页。
